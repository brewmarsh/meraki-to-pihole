🚨 Severity: HIGH
💡 Vulnerability: The application exposed several state-changing POST endpoints (`/update-meraki`, `/update-pihole`, `/update-interval`, and `/clear-log`) without any Cross-Site Request Forgery (CSRF) protection. Even though the application uses `IPWhitelistMiddleware`, malicious websites could execute actions by exploiting the victim's whitelisted IP address.
🎯 Impact: An attacker could trick an authenticated (whitelisted) user into visiting a malicious site that silently submits cross-origin POST requests, forcing the application to perform unauthorized actions like updating sync intervals, triggering manual syncs, or clearing logs.
🔧 Fix: Implemented a robust `CSRFProtectionMiddleware` that intercepts all `POST`, `PUT`, `DELETE`, and `PATCH` requests and verifies the presence of the `X-Requested-With: XMLHttpRequest` header. This standard protection mechanism blocks simple cross-origin requests because modern browsers forbid custom headers in simple form submissions. Updated frontend `fetch` calls and API test suites to supply the required header.
✅ Verification: Tested via unit tests ensuring a 403 Forbidden is returned for POST requests lacking the header, and normal 200 responses are returned when the header is present. Verified using `poetry run pytest`.
