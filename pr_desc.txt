🚨 Severity: HIGH

💡 Vulnerability: The application exposed state-changing POST endpoints (`/update-meraki`, `/update-pihole`, `/update-interval`, `/clear-log`) without inherent Cross-Site Request Forgery (CSRF) protections. It relied either on session cookies or the assumption that API calls were only made via frontend `fetch`, which allowed malicious websites to forge cross-origin requests.

🎯 Impact: An attacker could trick an authenticated user into submitting malicious requests, potentially changing application settings (like the sync interval), clearing logs, or initiating unauthorized sync processes without the user's consent or knowledge.

🔧 Fix:
1. Implemented a custom `CSRFProtectionMiddleware` in `app/app.py` that intercepts all `POST`, `PUT`, `DELETE`, and `PATCH` requests and strictly requires the `X-Requested-With: XMLHttpRequest` custom header, returning 403 Forbidden if absent. This relies on the browser's Same-Origin Policy, which prevents cross-origin requests from containing custom headers unless explicitly allowed by CORS.
2. Updated all frontend `fetch` calls in `app/templates/index.html` to append this required header.
3. Updated automated API testing clients in the test suite to include the required header to prevent false-positive failures.

✅ Verification: The test suite was fully run (`poetry run pytest`), and all 30 tests pass. A targeted check was completed to ensure manual API requests without the header return 403 Forbidden.
