🚨 Severity: HIGH
💡 Vulnerability: The application was missing Cross-Site Request Forgery (CSRF) protection on sensitive POST endpoints (e.g., `/update-interval`, `/clear-log`, `/update-meraki`, `/update-pihole`), allowing attackers to potentially forge requests from authenticated users.
🎯 Impact: Attackers could trick authenticated users into executing unwanted actions, such as clearing logs or changing settings, potentially leading to unauthorized system modifications.
🔧 Fix: Implemented `CSRFProtectionMiddleware` in FastAPI to require a custom header (`X-Requested-With: XMLHttpRequest`) for state-changing HTTP methods. Updated frontend fetch calls and tests to include this header. This provides robust defense as browsers block simple cross-origin form submissions containing this custom header.
✅ Verification: Ran `pytest` to ensure all tests, including new negative tests for CSRF failures, pass successfully.
