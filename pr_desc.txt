🚨 Severity: HIGH
💡 Vulnerability: The application relied on `IPWhitelistMiddleware` as the sole form of access control. While this restricts external access, it fails to protect against Cross-Site Request Forgery (CSRF). Malicious requests originating from a whitelisted user's browser inherently possess the whitelisted IP, allowing attackers to forge state-changing requests (like modifying the sync interval or clearing logs).
🎯 Impact: An attacker could trick an authenticated/whitelisted user into submitting a state-changing POST request, causing unintended consequences like deleting logs or maliciously altering application configurations.
🔧 Fix: Implemented `CSRFMiddleware` to enforce the presence of an `X-Requested-With: XMLHttpRequest` header on all state-changing endpoints (POST, PUT, DELETE, PATCH). Updated the frontend `fetch` requests and backend tests to include this custom header, effectively blocking simple cross-origin form submissions.
✅ Verification: Ran `pytest` locally to ensure all API endpoints return `403` when the header is missing, and that standard application functionality and tests operate successfully with the header present.
