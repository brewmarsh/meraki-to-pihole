🚨 Severity: HIGH
💡 Vulnerability: The application exposed several state-mutating POST endpoints (`/update-meraki`, `/update-pihole`, `/update-interval`, `/clear-log`) without any Cross-Site Request Forgery (CSRF) protection.
🎯 Impact: This allowed attackers to trick authenticated users into executing unwanted actions (e.g. clearing logs, triggering syncs, modifying the sync interval) if they visited a malicious site while having an active session or IP access.
🔧 Fix: Implemented a global `CSRFMiddleware` that verifies a custom header (`X-Requested-With: XMLHttpRequest`) is present on all state-mutating HTTP methods (POST, PUT, DELETE, PATCH). Updated the frontend `fetch` calls and all automated tests to include this header.
✅ Verification: Ran `poetry run pytest tests/` which all pass with the new CSRF protection in place, ensuring no regressions.
