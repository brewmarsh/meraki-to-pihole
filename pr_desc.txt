🚨 Severity: HIGH
💡 Vulnerability: The application was missing Cross-Site Request Forgery (CSRF) protection on state-changing API endpoints (e.g. POST, PUT, DELETE), making it vulnerable to simple cross-origin requests from malicious sites that the user might visit, despite the presence of IP Whitelisting.
🎯 Impact: Attackers could trick users into executing unwanted actions (like modifying the sync interval, or triggering data syncs) on the application by exploiting their existing trust/IP context if they visit a malicious site.
🔧 Fix: Implemented `CSRFMiddleware` that requires an `X-Requested-With: XMLHttpRequest` header for all state-changing API methods. This prevents simple cross-origin requests from being executed without a pre-flight CORS check, protecting the endpoints. The frontend `fetch` calls and corresponding tests were also updated to include this header.
✅ Verification: Review the added `CSRFMiddleware` logic in `app/app.py`, the updated `fetch` requests in `app/templates/index.html`, and verify the test suite passes with the new header requirements using `poetry run pytest`.
