💡 What: Filter the devices fetched from Meraki by `networkId` (if configured) and `model` (e.g., 'MS' or 'MX') *before* passing them to the ThreadPoolExecutor in `get_all_relevant_meraki_clients`.
🎯 Why: Submitting all devices to the thread pool, only for the inner functions (`_get_fixed_ip_assignments_from_switch`, etc) to ignore them or make unnecessary API calls, causes an N+1 API call bottleneck on large orgs with many unrelated devices.
📊 Impact: Eliminates unnecessary N+1 API calls for devices that don't match the network IDs or model types, significantly speeding up the Meraki sync process on large organizations.
🔬 Measurement: Compare the execution time of `get_all_relevant_meraki_clients` with and without network filtering on a large Meraki organization.
