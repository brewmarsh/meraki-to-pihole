🚨 Severity: HIGH
💡 Vulnerability: The application exposed state-changing endpoints (`/update-meraki`, `/update-pihole`, `/update-interval`, `/clear-log`) without any Cross-Site Request Forgery (CSRF) protection. Even when IP whitelisting is used, CSRF is still a threat because malicious requests originating from the user's browser will inherently possess the whitelisted IP.
🎯 Impact: An attacker could trick an authenticated or whitelisted user into submitting a request to these endpoints from a malicious site, allowing them to unexpectedly sync data, change the sync interval, or clear logs.
🔧 Fix: Implemented a `CSRFProtectionMiddleware` that requires the `X-Requested-With: XMLHttpRequest` header on all state-changing requests (POST, PUT, PATCH, DELETE). Updated frontend `fetch` calls and automated tests to include this header. This provides robust defense for AJAX APIs without token overhead.
✅ Verification: Ran `pytest` to ensure all tests pass, including a new `test_csrf.py` that explicitly verifies requests without the header or with an invalid header are rejected with a 403 Forbidden status, while requests with the correct header succeed.
