🚨 Severity: HIGH
💡 Vulnerability: The FastAPI application lacked Cross-Site Request Forgery (CSRF) protection on state-changing API endpoints (like `/update-meraki`, `/update-pihole`, `/update-interval`, and `/clear-log`).
🎯 Impact: A malicious website could trick an authenticated user's browser into making state-changing requests to the application, potentially clearing logs, altering sync intervals, or triggering unneeded syncs without the user's consent.
🔧 Fix: Implemented `CSRFProtectionMiddleware` to enforce the presence of an `X-Requested-With: XMLHttpRequest` header on all `POST`, `PUT`, `DELETE`, and `PATCH` requests. This leverages standard browser cross-origin protections. Updated the frontend `fetch` calls and the backend test suite to include this header. Added it right before `SecurityHeadersMiddleware` to ensure security headers are still served on a 403 Forbidden response.
✅ Verification: Ran the full backend test suite (`poetry run pytest`), verifying the middleware blocks requests missing the header and that all expected requests pass successfully.
